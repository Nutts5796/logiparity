# JSON report schema, version 1

The machine-readable [JSON Schema](report-schema.json) ships in the package. New optional properties may be added to schemaVersion 1; readers must tolerate unknown fields. Required meanings and money/time units remain stable. Removing fields or changing units requires a new schema version. Readers of older reports may encounter conflict `line` properties and display-string uncertain keys; new reports use physical `row` and key-part arrays. Version 1.1.0 is unreleased, so its review changes are included before publication.

The root requires schemaVersion, entities and findings. Optional patterns.minCount is at least 3 (default 3). groups preserve exact findingIndexes and never contain fewer members than minCount. coverage.explained counts the union of supported pattern members and accounted aggregate findings; needsReview counts the remaining findings. Accounting does not change failure policy.

Each finding has type, entity, source, key, field and message. Types are missing_in_source, extra_in_source, field_mismatch, aggregate_mismatch, duplicate_key, duplicate_value, invalid_value and source_error. expected and actual are optional normalized scalars. invalid_value includes its physical row and, when available, the valid reference value. duplicate_value has relatedKeys and optional amounts; a repeated tender alone is not evidence of duplicate payment. Rollup conflicts use values containing row and value, rather than invented expected/actual values. Composite keys retain keyParts. Entity pluralLabel is an optional display noun.

Money is a decimal integer minor-unit string. Datetimes are UTC epoch milliseconds. Optional currency identifies monetary findings. Aggregate valuesByCurrency and rawValuesByCurrency partition currencies; currencies are never converted or combined. rawValues, excludedRows, sourceStatus and uncertainKeys distinguish raw input, retained/certain inputs, unsupported mappings and failed reads. uncertainKeys contains arrays of key parts, including a one-element array for a simple key.

Reconciliation is keyed by source. Its identity is source total minus reference total equals missingRows.amount + extraRows.amount + valueDifferences.amount + sum(patterns.amount) + uncertain.amount + remainder. Each contribution is filtered by the aggregate's own where clause. Pattern amounts sum qualifying row contributions, rather than multiplying the whole pattern count. Tolerated or unsupported changes remain in the remainder. Zero remainder means the aggregate is accounted for; individual invalid values and one-off differences still require review. Mixed-currency totals remain partitioned and never receive a misleading combined reconciliation.

Patterns describe observations. Timezone hints require offset-free source values and a quarter-hour delta; page-boundary hints require pagination or matching configured page-size evidence. Blank values never form mapping or delta patterns. Groups retain every underlying finding and blocking status.

Object properties follow configuration order; findings sort naturally by entity, key, field, source and type. There are no generated clocks or random identifiers in normalized comparison reports. Source errors can include input paths and observed locations, so diagnostics can vary by environment. Human labels and formatted values are supplied separately from configuration.

## Package exports and scenario reports

Import `logiparity/report-schema.json` and `logiparity/scenario-report-schema.json` (JSON import attributes depend on your runtime), or read the files under docs/ in the installed package. Their versioned raw `$id` URLs identify the 1.1.0 tag; they resolve publicly after publication. Validators can register both local schemas without network access.

The [scenario schema](scenario-report-schema.json) describes `kind: scenario`, events, invariants, affectedOrderCount, runtime errors and optional nested Parity. Both wire schemas use version 1: consumers must tolerate additive optional fields; required meanings or money/time units cannot change without a schema version change. Runtime error reports may contain only the state collected before failure.

Parity finding extensions include accounting, referencePosition, amounts, evidence, relatedKeys and optional review hint. Aggregate extensions include uncertainKeys and independent reconciliationByCurrency; group extensions include cause, stride and exact keys. A truncated report explicitly sets truncated and includes a source error. Every generated/parsed report in the automated test suite goes through the shared schema validator, including nested scenario parity.
