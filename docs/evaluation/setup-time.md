# Time to first correct configuration — measurement protocol

**Not measured.** This file is a protocol and empty results table, not evidence that suggest saves time. The owner or a human participant supplies actual stopwatch times. Do not infer manual effort from command execution duration.

Use the synthetic healthy delivery demo's downloaded CSV and XLSX for the same closed day. Collect the files before timing; retain their checksums, row counts and expected field list. Require all shared fields (shipment ID, status, driver payout and delivered time), correct key, strict money and explicit source timezone. Do not include installation/download time in one workflow but exclude it from the other.

Use two workflows on equivalent tasks: (A) write the YAML manually from the schema documentation; (B) run suggest and resolve every key/mapping/type/unit/zone TODO. Counterbalance the order across anonymous trial codes, or record prior familiarity if only one person participates. Start the stopwatch when the task and sample schema are shown. Stop when validate and a complete check both succeed with every required field compared and the expected healthy result. Validation alone does not open sources and is not a sufficient endpoint.

Record elapsed seconds, validation/check attempts, fields deliberately excluded (a completed primary trial should exclude none), unresolved guesses and help needed. Keep a blocked/failed trial in the table; do not discard it. Repeat the task on a fresh equivalent fixture, not the same already-solved YAML. Record the LogiParity/Node version and sample hashes alongside the results. Optional JSON sample trials need the actual endpoint mapping and count/pagination review and should be reported separately.
