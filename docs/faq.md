# Frequently asked questions

**Can I use production data or inject production events?** Use only test/staging targets and synthetic or appropriately controlled test data. Environment declarations do not identify a production hostname. Scenario mutations require explicit allowMutations and an allowedHosts list, and have no rollback.

**What is compared?** The first source in an entity is the reference; other sources are joined by the canonical key. Missing/extra records, duplicate keys, scalar mismatches and configured aggregates become findings. The first duplicate row is retained for matching; the retained first row counts once in totals, with raw input and excluded rows shown when they differ. Invalid cells are per-row findings; more than maxInvalidRows invalid rows fail the source. Source failures exit 2 and suppress misleading incomplete comparisons.

**Why did a one-cent difference appear?** Monetary inputs must be decimal strings, not floating-point numbers. Normalization converts to exact bigint minor units; tolerance is an integer in those units. The intentionally buggy demo export rounds some values incorrectly. HTML, Markdown and console show configured currency amounts with a difference. JSON keeps exact minor-unit values.

**Where are raw dates and money?** JSON retains numeric UTC epoch milliseconds and integer minor units. Human formats, including JUnit, show readable dates and currencies with a separate difference; report.displayTimezone defaults to UTC. Numeric fields are not guessed to be dates. Set source timezones explicitly for offsetless timestamps; do not reinterpret the injected timezone bug to hide it.

**Why can all sources agree while a scenario fails?** An order can disappear from every surface or be assigned twice in independent assignment records. Domain invariants compare baseline and final state; post-scenario Parity independently checks the final surfaces. Both results remain visible.

**Why do UI reads fail after restarting the demo?** Restarting invalidates synthetic login sessions. Repeat `npm run demo:login` in a source checkout only, or `npx logiparity demo login` for an installed demo, then export again. Configure storageState, table/rows/field selectors, readiness, pagination and allowed origins. Virtualized tables, service workers and WebSockets are unsupported by the snapshot adapter. Failure screenshots can contain visible test data.

**Can SQL modify data?** The adapter validates a restricted SELECT grammar before connecting and uses a READ ONLY transaction. Use a dedicated read-only staging role; privileged side effects hidden in database objects are outside a universal sandbox guarantee. Development fixture setup is restricted to disposable loopback databases and is not packaged as the read adapter.

**Does it send data to AI by default?** No. Normal checks/scenarios never invoke AI. AI commands default to a local payload preview; --send and all three provider variables are required. Structured redaction is not general PII detection. Outputs are new marked drafts and never execute automatically; see [AI reference](ai.md).

**How large can datasets be?** Functional checks cover 100,000 records per source for the engine and streaming adapters. Memory also depends on indexed records, mapped fields, XLSX shared strings and findings.

**Do I need PostgreSQL/Chromium to try the quickstart?** The API/CSV/XLSX quickstart needs Node/npm only. Chromium is needed for UI sources, and a database for SQL sources. The complete contributor suite additionally needs xmllint and disposable PostgreSQL fixtures.

**Why is the npm tarball larger than the TypeScript sources?** It includes six compiled first-party workspaces, embedded fonts, synthetic fixtures and license texts. Third-party dependencies are exact-pinned normal packages; only Playwright and PostgreSQL are optional peers. Installing it does not fetch private @logiparity packages or download browsers. Chromium is installed separately for UI, or comes in the Docker image. First-party tests, auth state and generated reports/exports are excluded.

**How do I install the CLI?** Run `npm install --save-dev --save-exact logiparity`, then use `./node_modules/.bin/logiparity`. Versioned GitHub tarballs with SHA-256 files are another option; see the [release guide](release.md).

**How is this different from DataComPy, DuckDB, reladiff, Reconlify and duckdiff?** Pairwise diffing is already well covered. Their own READMEs describe [DataComPy](https://github.com/capitalone/datacompy/blob/main/README.md) for DataFrame/table backends, [DuckDB](https://github.com/duckdb/duckdb/blob/main/README.md) for embedded analytical SQL, [reladiff](https://github.com/erezsh/reladiff/blob/master/README.md) for database-side hashing/partition diffing, [Reconlify](https://github.com/testuteab/reconlify-cli/blob/main/README.md) for local YAML-driven file/log reconciliation and [duckdiff](https://github.com/OmUniyal/duckdiff/blob/main/README.md) for N-way out-of-core file comparison and accepted mapping suggestions. LogiParity bundles live paginated REST/browser/SQL acquisition with file comparison, strict money/time parsing and cause/total investigation in one config. It indexes records in memory; database-native or out-of-core tools may fit larger datasets better. These are README-verified positioning notes, not performance measurements. See the [comparison](../README.md#how-it-differs-from-tools-you-already-use) and [evaluation limits](evaluation/README.md).

**Can suggest save setup time or prove a key is right?** Setup time is [not measured](evaluation/setup-time.md). The command reads only local samples and produces an intentionally blocked TODO draft, retaining unmatched columns. Sample uniqueness, name aliases and type shapes are evidence for review, not acceptance. No endpoint is called, normalization tolerance enabled or key chosen automatically; see [the recipe](recipes/suggest.md).
