# Contributing

Start with [AGENTS.md](AGENTS.md) for package boundaries, extension points and exact checks, and [architecture](docs/architecture.md) for data flow and the public/internal API boundary.

Bug reports, synthetic reproductions, documentation improvements and adapter work are welcome. Start with a small issue describing the problem and expected behavior. For a larger change, discuss the proposed interface before implementing it. The [roadmap](docs/roadmap.md) lists starter tasks.

## Setup

Use Node.js 22 or later; CI tests Node 22, 24 and 26.

```sh
git clone https://github.com/Nutts5796/logiparity.git
cd logiparity
npm ci
npm run build
npx logiparity install-browser --with-deps
```

The full suite needs `xmllint` and PostgreSQL development binaries. On Debian or Ubuntu install `libxml2-utils` and PostgreSQL. Tests can create disposable local clusters through initdb/pg_ctl, or use LOGIPARITY_TEST_DATABASE_URL pointing to a disposable **loopback database named logiparity_test**. They refuse other fixture targets and remove their temporary schemas. Run cluster creation as a non-root user.

## Checks

```sh
npm run lint
npm run typecheck
npm test
npm run test:e2e
npm run check:docs
```

The e2e command builds first. Tests require loopback networking and use synthetic data, real Chromium, disposable PostgreSQL and mock AI providers. No real AI key is required. Add regression tests for behavior changes and adapter failures. Line coverage across core, adapters, scenarios and CLI must stay at or above 80%.

For packaging, dependency or CI changes, also run:

```sh
npm run test:package
npm run test:quickstart
npm run test:docker
```

The package check verifies an empty-cache offline installation and public API declarations. Docker checks need a working local engine. See [CI](docs/ci.md) and [release testing](docs/release.md).

## Style and pull requests

Use strict TypeScript, ESM and clear errors that identify the source, record or config path. Avoid `any`. Preserve decimal text for money unless numeric input is explicitly enabled. Keep runtime dependency versions exact and permissively licensed; optional peers use tested compatible ranges. regenerate `docs/dependencies.md` with `node scripts/dependencies.mjs` after changing runtime dependencies.

Use Conventional Commits, as in the M1–M10 history, such as `fix: detect capped REST pages`. In the pull request, explain the user-visible problem, resulting behavior and checks performed. Include minimal synthetic fixtures, never tokens, browser storageState, private endpoints or customer records. Keep AI tests local and mock-based. Follow the [code of conduct](CODE_OF_CONDUCT.md), and use [private vulnerability reporting](SECURITY.md) for security issues.

Run `npm run format` before committing. CI checks Prettier with a 120-column print width. Embedded documentation examples remain literal because the quickstart executes them and compares the staging YAML with init. Verified upstream schema and license bytes are excluded from formatting.
